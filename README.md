# Tech Diglot • Новости и английский

Telegram-канал с короткими новостями о технологиях и 3–4 английскими словами в каждом посте. Сначала — цепляющий заголовок полужирным шрифтом, затем 2–3 коротких абзаца; английские слова не выделяются. Перевод и транскрипция публикуются от имени бота в комментариях под соответствующим постом.

## Публикация

GitHub Actions запускается в 06:00, 11:00 и 16:00 UTC — 09:00, 14:00 и 19:00 по Москве. GitHub может задерживать запуск расписания. Каждый запуск отправляет один пост. Когда очередь пуста, бот ищет новости за последние 48 часов через Google Search Grounding. Ответ без реальных поисковых запросов и ссылок из метаданных не принимается. При недоступности поисковой квоты используется резерв: Google News RSS (технологии, наука, ИИ) и Хабр. Google News-ссылки раскрываются до сайта издания; перед написанием постов бот читает статьи и проверяет их фотографии.

В каждом посте **от 1 до 3 разных изображений** из исходной статьи. Две или три фотографии отправляются одним альбомом с общей подписью. Логотипы, маленькие картинки, рекомендации вне статьи и разные размеры одной фотографии отбрасываются. URL и хеши картинок сохраняются в истории для исключения повторов. Если фотографий нет, источник пропускается до генерации; при сбое фотографии готовый пост остаётся в очереди и не публикуется без изображения.

Gemini пишет русский черновик и выбирает точные русские фрагменты для замены. Код сам вставляет английские слова обычным шрифтом: содержимое словаря не может расходиться с текстом. Текст и структурированный словарь проходят проверку длины, количества слов и соответствия друг другу. Для генерации используется JSON-схема; некорректный ответ запрашивается повторно. Ссылка на источник добавляется под словами в комментарии. `history.json` хранит последние 90 публикаций для исключения повторных источников.

Бот ждёт автоматическую копию своего поста в привязанной группе обсуждения. Копия определяется по `is_automatic_forward`, ID исходного канала и ID исходного поста в `forward_origin`. Комментарий «Слова в посте» отправляется ответом на **ID сообщения группы**, без межчатового ответа. Ошибка не приводит к отдельному словарю в канале или группе.

## Настройка

Добавьте бота администратором канала с правом публикации сообщений и администратором привязанной группы обсуждения. В настройках канала включите обсуждение и автоматическую пересылку постов в группу. Бот получает обновления через `getUpdates`; webhook и второй потребитель обновлений этому боту не нужны.

GitHub Secrets:

- `GEMINI_API_KEY` — ключ Google AI Studio.
- `TELEGRAM_BOT_TOKEN` — токен бота.
- `TELEGRAM_CHAT_ID` — ID канала (`-100…`) или `@username`.
- `DISCUSSION_CHAT_ID` — необязательная дополнительная проверка ID группы. Группа определяется автоматически через `getChat.linked_chat_id`; неверный ID останавливает публикацию до отправки поста.

Необязательная GitHub Variable `GEMINI_MODELS` задаёт список моделей через запятую. По умолчанию используются `gemini-3.1-flash-lite,gemini-3.8-flash`. `GEMINI_SEARCH_MODELS` отдельно задаёт модели поиска (по умолчанию `gemini-3.8-flash`). `NEWS_MODE=rss` отключает Grounding; по умолчанию `NEWS_MODE=grounding` с резервом RSS. Эти значения доступны как GitHub Variables.

Квота Search grounding отдельная от квоты генерации текста. Проверьте её для своего проекта в [AI Studio](https://aistudio.google.com/rate-limit). Если API возвращает 429, бот использует RSS; это не устраняет ограничение Google. Доступность старых моделей определяется API, а не наличием строки в таблице квот. В локальном запуске поддерживается игнорируемый Git файлом `.env` в папке проекта; значения окружения имеют приоритет.

## Локальная проверка

Python 3.11 или новее:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python bot.py --check
.venv/bin/python bot.py --preview preview.json
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

`--check` проверяет Telegram и читает очередь без публикации. `--preview` генерирует три поста и сохраняет JSON без изменения очереди. Запуск `python bot.py` **публикует один пост и комментарий «Слова в посте»**. `python bot.py --publish-all` публикует всю очередь подряд.

В GitHub Actions → Daily Diglot Weave Digest → Run workflow доступны `publish`, `publish-all`, `check` и `profile`. `publish-all` публикует всю очередь подряд, либо генерирует и публикует три поста, если очередь пуста. Расписание всегда публикует по одному посту. Проверки на push и pull request не используют секреты и ничего не публикуют. Публикация доступна только из `main`; параллельные запуски сериализуются.

## Состояние и восстановление

`queue.json` сохраняется атомарно после каждого шага. Пост удаляется из очереди только после подтверждения комментария. При ошибке словаря сохраняются `channel_message_id` и `discussion_message_id`, поэтому следующий запуск продолжает этот пост без повторной публикации в канале. Состояние коммитится GitHub Actions даже при ошибке отправки; ошибки сохранения в Git больше не скрываются.

При таймауте отправки Telegram мог уже принять сообщение. Бот сохраняет `post_delivery_unknown` или `comment_delivery_unknown` и останавливает автоматические повторы. Проверьте Telegram: если сообщение доставлено, внесите его ID в соответствующее поле первой записи очереди; если нет — удалите флаг неизвестной доставки. После удаления флага следующий запуск продолжит публикацию. Для группы нужен ID копии поста, а не ID канала. Не удаляйте запись целиком, пока не проверите доставку.

Если автоматическая копия поста не найдена, проверьте права бота, привязку группы и отсутствие другого процесса `getUpdates`. Telegram хранит обновления не дольше 24 часов; для более старой копии потребуется вручную указать `discussion_message_id` в очереди.

## Профиль бота

Имя и описания хранятся в `assets/profile.json`, тёмная аватарка — в `assets/avatar.jpg`, бирюзовая — в `assets/discussion-avatar.jpg`. `python configure_bot.py` обновляет профиль бота, аватарку и описание канала, аватарку и описание группы обсуждения через Telegram Bot API и проверяет ответы API. `--chats-only` обновляет только канал и группу. Для изменения профилей чатов боту нужно право `can_change_info`. Отображаемое имя изменяется; существующий `@username` сохраняется. Используются `setMyName`, `setMyDescription`, `setMyShortDescription`, `setMyProfilePhoto`, `setChatPhoto` и `setChatDescription`.
